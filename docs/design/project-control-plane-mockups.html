nightdesk · design review · round 4 · 2026-07-12

The project control plane

Round 4 locks the frame: a project is the control plane for its work — Desk stays untouched as the cross-everything signal. Four tabs: Overview (state), Plan (roadmap), History (record), Settings (config, lifted home). No timelines, no cost forecasts, no cards.

Rulings applied this round

  • Desk is out of scope. It stays the whole-of-nightdesk overview and the "which project needs me" signal. Project pages are the scoped depth behind it; overlap is deliberate.
  • Settings is a full tab. Every project-scoped setting lifts out of global Settings (identity, execution defaults, repo links, label defaults, crons, danger zone). Global Settings→Projects becomes a thin deep-link list. All backend-real; pure frontend lift.
  • Plan is a roadmap, not a schedule. No "tonight", no times, no cost forecasts. The backlog groups into workstreams — each connected component of the dependency graph is its own lane, nodes laid left→right by depth with edges that branch and merge (n levels, any number of parallel streams); unlinked tickets pool as singles. Badges answer only "will this ever run and why" (queued / after ↑ / cron / blocked / no path ⚠ / on hold). Breakdown workbench: prose intent → proposed decomposition → edit → batch-create with deps wired; agentic generation ships in the later agentic-workflows pass.
  • Inbox stays inbox. The issues/ideas reframe and the flesh-out agent are parked for the agentic pass.
  • No duplicated workflows. Overview's running section is plain rows (title, elapsed, cost) — inspect and steer live on the ticket page. History carries forward unchanged. Settings gets a sticky section rail (with unsaved-change dots) and collapsible sections instead of scroll-hunting.
Trends → Analytics + project filter

Overview — the state of everything, one ledger, zero cards. Running is plain rows now — inspect/steer on the ticket page, no duplicated workflows.

Region legend — job · interaction · backend

1 Workstreams Each connected component of the dependency graph gets its own full-width lane, auto-named from its root ticket — "Workstream — GitLab write-back · 4 tickets". Nodes lay out left→right by topological depth; SVG edges show real branches and merges (the GitLab write-back diamond: one root branches into two parallel tickets, both merge into "Set MR status on merge"). Arbitrary depth and width are supported — this isn't limited to 3 buckets or single chains. new — connected-component grouping + depth-column layout is a client-side read over the existing TicketDependency DAG; no schema change. Merges are simply two-or-more TicketDependency edges pointing at one ticket, already representable today.
— Single tickets Anything with no dependency edges pools below the workstreams as plain ledger rows — same row anatomy as before (priority chip, kind glyph, title, path badge, verb), no graph chrome needed since there's nothing to draw. backend-real — same ticket fields as everywhere else on this page.
— Rollup line Header sentence counts workstreams and singles separately, then the same attention badges as before. No time claim anywhere — "queued" means the scheduler will place it, not when. new — same connected-component read, aggregated.
— Drag-to-wire Dragging from a singleton's gutter dot opens a live dashed edge that follows the cursor; releasing over a workstream node wires a "blocked by" dependency and folds the singleton into that stream — same write as the b picker, a faster gesture for adjacent rows. Shown mid-drag from "archive-obsolete-drafts" toward "rust preset" (Toolchain capacity), unattached. new UI — writes the same real TicketDependency edge; only the drag gesture is new.
— blocked / no-path fix affordance Inline "[fix ▾]" resolves the blocker (assign profile) without leaving the row; "no path" rows get a queue/schedule verb directly, not a link elsewhere. backend-real — profile assignment and queue are existing ticket operations.
2 Breakdown workbench A prose intent turns into 5 proposed ticket rows with pre-wired dependency elbows; per-row keep/drop before commit, one row shown mid-edit. Verb row batch-creates only the kept rows and wires TicketDependency edges in one call. backend-real — batch ticket create + TicketDependency wiring both exist today; this page composes existing single-ticket endpoints.
— Attribution line Explicit and honest: the agent-authored proposal shown here is a design preview — agentic generation of decompositions ships in a later pass. Manual breakdown (typing 5 rows by hand, wiring deps with the same picker as the backlog) is fully real today and produces the identical UI. new — the LLM call that drafts a decomposition from prose intent does not exist yet.
3 Schedule assurance Two real crons plus one honest sentence about tonight's window — no projection, no bar chart, no minute-precision claim. backend-real — cron cadence/last-fire/next-fire and the schedule window/slot-count are live scheduler fields.

History — unchanged (approved round 2). One dense ledger, numbers-only rollups, scrubbable time rail.

Callouts

①
Filter chips + searchhorizon: past, scoped to view — client-side filter over the loaded ledger window (All / Runs / Failures / Shipped / Repo / Lifecycle); search narrows by title/MR/issue text. Click a chip or type "/" to focus search. Backend need: none for filtering already-fetched pages, but "Shipped" as a first-class filter implies runs need a queryable shipped/merged flag, not just terminal status — currently inferred client-side from status+review-exit.
②
Day-grouped, interleaved ledgerhorizon: past, one line per event — reverse-chronological rows mixing run outcomes, lifecycle transitions, repo events (MR/issue), and cron fires under sticky day headers. Click a row to peek (transcript, diff, or MR) in place; hover surfaces the full title via native truncation tooltip. Backend need: a single unified activity/events feed endpoint (today runs, tickets, GitLab, and crons are four separate queries with different pagination and timestamp semantics — this view needs them pre-merged and cursor-paginated together).
③
Right-edge mini time railhorizon: past, fast scrub — month/week markers along a vertical line; click a marker to jump-scroll the ledger to that date, drag to scrub continuously. The Jun 28 marker is tinted ember to preflight a bad day before scrolling to it. Backend need: a lightweight date-histogram endpoint (event counts + failure counts per day) to place markers and color them without loading full day payloads up front.
·
Week-boundary rollup rowshorizon: past, numbers only — dashed numeric-only summary between weeks (runs, shipped, cost, success%); intentionally no generated prose digest per prior product direction. Not interactive. Backend need: weekly aggregate rollup (already computable from Trends' weekly series — reuse that endpoint rather than building a second aggregator).

Settings — every project-scoped setting in the project's own home. Sticky section rail with unsaved-change dots, collapsible sections, the dirty row with its sticky save bar. Pure frontend lift — zero new backend.

Remaining tensions

Roadmap lanes are derived, and derived things flicker. A ticket completing at night can promote three LATER rows to READY by morning — good, that's the point — but mid-session queue/wire actions also re-stage rows under your cursor. The build should re-stage on explicit action, not on poll, or planning will feel like standing on ice.
Breakdown needs a home for intent. The prose intent that generated a decomposition is worth keeping (it's the "why" behind five tickets), but there's no entity for it until milestones land in the agentic pass. Cheapest v1: stamp the intent text into each created ticket's description footer.
History's filters must be server-side on the activity endpoint from day one, or the Failures chip lies about anything beyond the loaded window.
